## 4. YOUTUBE BACKEND (package youtube)
- Interface YoutubeBackend { suspend fun resolve(url): ResolvedLink (single video or playlist); suspend fun details(videoId): VideoDetails; suspend fun refreshStreams(videoId): StreamSet }. Implementation NewPipeBackend wraps NewPipeExtractor, so another backend can replace it later.
- Implement the extractor's Downloader with a shared OkHttp client (HTTP/2, connection pool, 10 s connect, 20 s read, gzip, retries disabled at client level because retry logic is ours). Map HTTP 429 to the extractor's ReCaptchaException. Set Localization from the user's preferred audio language so metadata comes in their language.
- URL parser (pure Kotlin + tests): youtube.com/watch?v=, youtu.be/, /shorts/, /live/, /embed/, m.youtube.com, music.youtube.com, playlist?list=, with extra tracking params ignored. Android share target ACTION_SEND text/plain only (do NOT register VIEW handlers for youtube.com).
- Metadata fetching must be efficient: single-flight per videoId (concurrent callers share one deferred), LRU cache (32 entries, 10 min TTL), cancel the previous fetch when the input changes, 400 ms debounce on typing, hard timeout 20 s, thumbnail prefetch via Coil in parallel with stream parsing.
- Stream planning (StreamPlanner, pure, unit-tested): from the extractor streams build options.
  - Video: list distinct heights from video-only streams. MP4 path: H.264 (avc1) up to 1080p merged with AAC m4a. For 1440p, 2160p and anything without H.264: VP9 + Opus into WebM. Show a small "WebM" tag on those options. Include fps (60) and HDR tags when present. Estimate size = (video bytes + chosen audio bytes). Default selection = highest option <= defaultMaxQuality, else the nearest lower.
  - Audio only: best m4a/AAC stream, saved as .m4a without re-encoding.
  - Use progressive streams only if no video-only streams exist.
- Audio tracks: the extractor exposes multiple audio tracks per video. Before coding this, inspect the dependency JAR (javap) to confirm the exact API of AudioStream (track id, track name, audio Locale, audio track type such as ORIGINAL, DUBBED, DESCRIPTIVE, default flag) and adapt names; do not guess. Group streams by track id into AudioTrackOption(id, locale, type, displayName, bestStreamForMp4, bestStreamForWebm).
- AudioTrackSelector (pure, unit-tested) decision rules:
  1. If there is 0 or 1 track: use it, no UI decision (show only a compact info row).
  2. original = track typed ORIGINAL, else the default-flagged track, else the first one. Never auto-select DESCRIPTIVE tracks.
  3. pref = preferredAudioLanguage. If original.language == pref: choose original, NO prompt even if dubs exist (the row offers a quiet "Cambiar" link).
  4. Else if channel_audio_pref has a track available: choose it silently.
  5. Else if autoPickDubbed and a track in pref language exists: choose it silently.
  6. Else if askWhenAlternatives: show the audio picker (section 8.1) with preselection = track in pref language if it exists, else original. If askWhenAlternatives is false: choose pref-language track if it exists, else original.
  - Region variants (es-ES, es-419, es-MX) group under one language heading; within the same language prefer the region matching the device locale.
  - Playlists and batch jobs never prompt: apply steps 2–5 then fall back to original.
  - Sort in the picker: pref-language tracks first, then original, then the rest alphabetically by native language name.
- Error mapping to typed errors with friendly Spanish copy: age restricted or login required, private, removed or unavailable, geo-blocked, members-only/premium, live stream or premiere not finished, rate limited (429), network, unsupported URL, extractor parse failure (show an "actualiza la app" banner linking to the update check).

## 5. DOWNLOAD ENGINE (package download)
Goals: rigorous efficiency, resilience, true background operation.
- DownloadManager singleton owns a supervisor CoroutineScope. A Semaphore(maxConcurrentDownloads) limits simultaneous downloads. Queue ordered by priority then createdAt. Actions: enqueue, pause, resume, cancel, retry, prioritize ("Descargar primero"), pause all, resume all, clear finished.
- Per download pipeline: FETCHING (refresh stream URLs if older than 20 min or missing) → DOWNLOADING (video stream and audio stream downloaded concurrently with async) → MUXING → DONE.
- Chunked parallel download: each stream is split into 5 MiB range chunks (YouTube throttles large unchunked requests). Per stream, `connectionsPerStream` workers pull chunk indices from a channel. Writes use positional FileChannel writes into a pre-sized .part file in noBackupFilesDir/dl/<id>/. Use an 64 KiB buffer, no per-chunk allocations. Network work runs on Dispatchers.IO.limitedParallelism(12). OkHttp Dispatcher: maxRequests 24, maxRequestsPerHost 16.
- Resume: persist chunk completion bitmap every 2 s and on pause/cancel/stop. After process death restore the bitmap and continue. On resume validate .part length.
- Retries: up to 6 attempts per chunk with exponential backoff (0.5 s × 2^n) plus jitter, cap 20 s. HTTP 403/410 or an expired URL (expire= query parameter) triggers ONE single-flight refreshStreams per video then continues. HTTP 429 triggers a global 30 s cooldown. Loss of connectivity moves the item to WAITING_NETWORK and resumes automatically through ConnectivityManager.NetworkCallback (respect wifiOnly: if the active network is metered, wait).
- Disk: before starting require free space ≥ 1.15 × total; otherwise fail with DISK_FULL.
- Progress: atomic byte counters, a 250 ms sampler producing a conflated StateFlow<Map<Long, Progress>> (percent, bytesDone, speed, eta). Speed = moving average over 3 s, ETA from remaining/speed smoothed with EMA α 0.2. Database progress writes only every 2 s. Notification updates at most 1 per second per notification.
- Muxing: Android MediaExtractor + MediaMuxer, copying samples in 1 MiB buffers (no re-encode). MP4 output for H.264/AAC, WebM output for VP9/Opus. Mux directly into a MediaStore file descriptor: insert into MediaStore.Video (RELATIVE_PATH Movies/<AppName>) or MediaStore.Audio (Music/<AppName>) with IS_PENDING=1, write, then IS_PENDING=0. If direct muxing fails, mux to a temp file and copy. API 26–28: write to public directories with WRITE_EXTERNAL_STORAGE (maxSdkVersion 28). Audio-only downloads are written straight to MediaStore without muxing.
- After DONE: save thumbnail (maxres or hq, downscaled to 720 px wide WebP) and channel avatar (192 px) into filesDir/art/, extract dominant color with Palette, insert into videos, delete part files, update MediaStore title/artist.
- On start: orphan cleanup of dl/ folders with no matching row. Interrupted items (process death, reboot) are marked PAUSED, never auto-started from boot (Android 15 forbids starting dataSync foreground services from BOOT_COMPLETED). Instead show a notification "N descargas pausadas" with a "Reanudar" action.
